# Jurnal AI — Etapele 6, 7 și 8 (DeviceVault)

## Etapa 6: Date dintr-un API REST local (`json-server`)
- **Obiectiv:** Înlocuirea datelor statice din memorie cu o sursă persistentă REST API și tratarea stărilor asincrone.
- **Modificări implementate:**
    - Configurat `frontend/db.json` cu colecția `devices` și adăugat scriptul `"api": "json-server --watch db.json --port 3001"` în `frontend/package.json`.
    - Creat modulul `frontend/src/api.js` cu funcțiile `fetchDevices`, `fetchDevice`, `createDevice`, `updateDevice` și `deleteDevice`, incluzând verificarea `res.ok` și propagarea erorilor HTTP.
    - Implementată încărcarea inițială în `useEffect` (cu flag de curățare `ignore`) și afișarea stărilor condiționale de încărcare (`data-testid="loading"`) și eroare (`data-testid="error"`).

## Etapa 7: Formular controlat, validare și operații CRUD complete
- **Obiectiv:** Adăugarea dispozitivelor noi din interfață cu validare pe client și persistarea fiecărei modificări pe server înainte de actualizarea stării React.
- **Modificări implementate:**
    - Creat componenta `frontend/src/components/DeviceForm.jsx` cu input-uri controlate (`nume`, `camera`, `tip`), validare la trimitere, marcarea câmpurilor invalide cu `aria-invalid="true"`, dezactivarea butonului în timpul cererii (`submitting`) și resetarea câmpurilor după succes.
    - Legat operațiile **Adăugare (`POST`)**, **Comutare stare online/standby (`PATCH`)** și **Ștergere (`DELETE`)** la API înainte de actualizarea listei din interfață.
    - Adăugate atributele `data-testid` standard (`form`, `form-title`, `form-camera`, `form-tip`, `form-submit`, `item`, `item-toggle`, `item-title`, `item-delete`, `empty`) și verificată detectarea lor în consola browserului.

## Etapa 8: Rutare client-side (`react-router-dom`), pagină de detaliu și CSS Modules
- **Obiectiv:** Transformarea aplicației într-un SPA cu rute multiple fără reîncărcarea paginii și stilizare izolată prin CSS Modules.
- **Modificări implementate:**
    - Instalat `react-router-dom` și învelit aplicația în `<BrowserRouter>` în `frontend/src/main.jsx`.
    - Refactorizat `frontend/src/App.jsx` ca layout principal cu bară de navigare `<NavLink>` (evidențiere rută activă) și `<Routes>` pentru:
        - `/` $\rightarrow$ `DevicesPage.jsx` (panoul principal Smart Home Hub, telemetria, formularul și lista de dispozitive);
        - `/devices/:id` $\rightarrow$ `DeviceDetaliuPage.jsx` (preia `:id` cu `useParams()`, încarcă dispozitivul din API prin `fetchDevice(id)`, permite comutarea stării, ștergerea cu `useNavigate()` și revenirea pe `/`);
        - `/despre` $\rightarrow$ `DesprePage.jsx` (prezentarea arhitecturii proiectului);
        - `*` $\rightarrow$ `NotFoundPage.jsx` (pagină 404 pentru rute inexistente).
    - Actualizat `frontend/src/components/DeviceCard.jsx` cu link-uri `<Link to="/devices/:id">` spre pagina de detaliu.
    - Creat `frontend/src/App.module.css` pentru stilizarea izolată (CSS Modules) a barei de navigare globale.

## Verificare finală
- Testate local atât serverul `json-server` (`http://localhost:3001/devices`), cât și aplicația Vite (`http://localhost:5173`): validarea formularului, persistența la `Refresh`, navigarea între toate cele 4 rute și absența erorilor în consolă.
